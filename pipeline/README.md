# MIE Pipeline Registry

## Overview
This directory contains the **Single Source of Truth** for the Market Intelligence Engine (MIE) daily batch pipeline. 
The `stages.yml` file defines every step, dependency, and command required to run the daily workflow.

## File Structure
- `stages.yml`: The registry of all pipeline stages.
- `README.md`: This documentation.

## How to Add a New Stage

To add a new stage to the pipeline (e.g., a new analytics module), follow these steps:

### 1. Implement the CLI Command
Ensure your logic is accessible via the `mie` CLI. 
*   Update `src/mie_lib/cli/mie.py` to add a handler for your command (e.g., `handle_my_new_stage`).
*   Ensure it accepts necessary arguments (or heavily defaults to `@config`).

### 2. Register in `stages.yml`
Add a new entry to the `stages` list in `pipeline/stages.yml`.

```yaml
- id: my_new_stage                 # Unique snake_case identifier
  name: "My New Analytics"         # Human-readable name for logs/UI
  mode: BATCH                      # BATCH | REAL-TIME | HYBRID
  command: my-new-command          # The 'mie' CLI command
  args: ["--arg1", "value"]        # List of arguments
  depends_on: ["previous_stage"]   # List of stage IDs that must finish first
  outputs: ["data/analytics/*.json"] # File patterns produced
  inputs: ["data/raw/*.parquet"]   # File patterns required
  retry: 0                         # Max retries (default 0)
  timeout_minutes: 15              # Hard timeout
  on_failure: warn                 # 'fail' (stop pipeline) or 'warn' (continue)
```

### 3. Fields Reference

| Field | Description | Required |
|Os|---|---|
| `id` | Unique identifier (snake_case). used in `depends_on`. | Yes |
| `name` | Human-readable display name. | Yes |
| `mode` | `BATCH` (daily cron), `REAL-TIME` (API), or `HYBRID`. | Yes |
| `command` | The `mie` CLI command to execute. | Yes |
| `args` | List of string arguments to pass to the command. | Yes |
| `depends_on` | List of stage `id`s that must complete successfully before this starts. | Yes |
| `outputs` | Glob patterns of files generated by this stage. Used for artifact tracking. | No |
| `inputs` | Glob patterns of files required by this stage. Used for lineage. | No |
| `retry` | Number of retries on failure (default 1 for critical, 0 for others). | No |
| `timeout_minutes` | Maximum runtime before SIGKILL. | Yes |
| `on_failure` | `fail`: Abort pipeline. `warn`: Log error but proceed. `skip`: Skip dependents. | Yes |

## Maintenance Rules
1.  **Order Matters**: While `depends_on` defines the graph, keep the YAML file roughly ordered by execution phase for readability.
2.  **No Hidden Scripts**: Do not run raw Python scripts (`python script.py`) unless absolutely necessary. Wrap them in `mie` CLI commands.
3.  **Idempotency**: Stages should be idempotent. Re-running a completed stage should be safe.
4.  **Failure Policy**: 
    *   **Core Ingestion (Raw Data)**: Must be `on_failure: fail`.
    *   **Downstream Analytics**: Should be `on_failure: warn` to ensure partial reports are still generated.
